## Read before coding
Read README.md, BRD.md, SRS.md, WORK_PLAN.md, confirmed_baseline.json, decisions.json, requirements.json, backlog.json and the relevant fixtures/tests. Identify one task and human owner. Verify that the repository and API contract being used are the agreed ones. No existing application repository or access credential is supplied by this package.

## Do not assume
An OPEN decision blocks only dependent work. A prerequisite task must be DONE with linked evidence. Proposed SRS details require their associated decision to be resolved; the document itself does not prove approval. Null means unknown. Never replace it with zero, a guessed date, a random identity, a model score, a default premium or the reference policy values. Do not silently choose auth, ORM, hosting, paid services, API endpoints for partners, consent scope, finance inputs, thresholds, clinical facts or extra business rules. No reply and elapsed time are not approval.

## Ask a concrete question
State task ID, requirement ID, decision ID, exact missing choice/value, affected behavior, options/recommendation and independent work that can continue. Ask the human task owner/team, not an external stakeholder unless explicitly authorized. Record the exact answer, answering person and date; update decisions and affected contracts/tests. Do not resolve the register merely because the agent prefers an option. Do not guess agreement from an obsolete earlier plan.

## Safe execution
Continue source review, reference arithmetic, requirement mapping, isolated tests with supplied values and questions while blocked. Do not produce dependent application behavior until the decision is resolved. External access may be mocked only in an agreed mode and must be labelled. No live payments or real health data. Do not bypass access with a client-side role selector or fabricated token. Do not invent successful API results when a service fails. Preserve original submissions, assessment versions and financial entries.

## Parallel work and changes
Human owners may run their coding agents independently. Work on bounded tasks with agreed shared-file ownership. Coordinate shared models, migrations and the API contract before edits. No changes to scope, contract, dependency versions or fixtures without updating the linked decision and affected tasks. A contract mock used for development is not an integrated backend. Do not call a flag proven fraud; do not claim model training, compliance, certification or measured savings without evidence.

## Verification and handoff
Run the tests appropriate to the task. Capture exact commands, build/revision identifier, input fixture IDs and observed results. Acceptance tests start NOT_RUN; unavailable fixtures are BLOCKED, never PASSED. Include data provenance, mock mode, unresolved decisions and limitations in the handoff. Ask the named reviewer to inspect changes. Mark DONE only when requirements, decisions, prerequisites and evidence are satisfied. Silas records these outcomes and the final demo capability matrix.
